MARINOVANI — админка

1. Скопируй содержимое архива в D:\My Files\Desktop\marinovani.
   Согласись на замену файлов и объединение папок backend/assets.
   Архив не содержит .env, базу, токены и пользовательские заявки.

2. На компьютере, в терминале этой репы, по одной команде:
   git add admin.html assets/css/admin.css assets/js/admin.js backend/admin.py backend/api.py backend/test_admin.py compose.yaml Dockerfile.site index.html
   git commit -m "Add owner registration and booking dashboard"
   git push

3. В SSH:
   cd ~/PC-CLUB-site
   git pull --ff-only origin master

   Если pull выдаёт ошибку, остановись и сохрани её текст.
   При успешном обновлении:
   openssl rand -hex 24

   Скопируй выведенную случайную строку — это код первичной регистрации.
   Следующей командой добавь его в .env, заменив ВАШ_КОД своей строкой:
   printf '\nADMIN_SETUP_KEY=ВАШ_КОД\n' >> .env

   Код регистрации не отправляй в чат и не коммить.
   Затем:
   docker compose up -d --build

   Проверки защиты (не создают и не изменяют реальные заявки):
   docker compose exec api python -m unittest test_admin -v

4. Открой http://89.127.206.24:8101/admin.html
   Введи код регистрации, придумай логин и отдельный пароль (не меньше 12 символов).
   После регистрации откроется список заявок.
   Уже существовавшие заявки тоже появятся, с начальным статусом «Новая».

5. После первой успешной регистрации удали код из настроек:
   sed -i '/^ADMIN_SETUP_KEY=/d' .env
   docker compose up -d api

   Аккаунт сохранится в PostgreSQL. Последующие посещения — вход по логину/паролю.
   Повторная регистрация администратора запрещена даже при оставленном коде.

6. Проверка:
   - Выйди из кабинета. Не должно быть доступа к списку заявок.
   - Зайди снова: логин/пароль должны работать.
   - Отправь заявку через сайт, затем обнови кабинет.
   - Новая заявка должна появиться с источником «Сайт».
   - Заявка из Telegram должна появиться с источником «Telegram».
   - Подтверди заявку, обнови страницу: статус должен сохраниться.

Важно: смена статуса не отправляет клиенту SMS/Telegram-подтверждение.
С клиентом связывается администратор. Текущее уведомление владельцу в Telegram остаётся.
Автоматического распределения свободных мест и защиты от пересечений времени нет.

Пароли хешируются scrypt, вход действует 8 часов, сессии в PostgreSQL.
Список закрыт авторизацией, изменения защищены CSRF-токеном.
На текущем HTTP-адресе соединение не зашифровано: используй отдельный учебный пароль.
Для эксплуатации с настоящими данными нужен HTTPS, после его настройки добавь:
ADMIN_COOKIE_SECURE=true
в серверный .env и перезапусти API.

База расширяется автоматически при запуске API. Удалять том pgdata не нужно.
При ошибке:
docker compose logs --tail=40 api
